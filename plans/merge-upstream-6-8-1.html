06 · Merge strategy

Because the two histories have no common merge-base, a normal git merge upstream/master will produce a giant conflict pile. Treat this as a rebase-and-port:

  1. Checkout upstream/master (v6.8.1) as the new base — take all 382 commits.
  2. Re-apply local-only work on top — Bible layer, RCCG TPHB, bible splitter, lite controller, custom-outputs persistence, latency fixes (the 12 local commits replayed as patches).
  3. Skip telemetry, Butterchurn, FirstRunTour, ObsDock, Vitest rewrite.
  4. Resolve the two conflict zones — the modal/bridge system and the output routing (local custom-outputs vs upstream clean-path routing). Decide one winner per zone; don't try to keep both.
  5. Re-verify with the local Vitest suite + a manual projection smoke test (start backend, open outputs, load a verse).

Suggested jj/git work order:

# treat upstream as base
git checkout upstream/master -b merge-base-6.8.1
# replay local features as patches
git format-patch -k refs/heads/main --shared/bible src/components/Bible src/utils/bibleSplitter.js src/pages/LiteController.jsx src/pages/DynamicOutputRoute.jsx
# then reconcile conflicts by hand, feature by feature
