Method 05

Precompute the Pixel Fit

The output autosizer is the documented #1 performance bottleneck. The fix is not to make the measuring faster — it's to stop measuring.

The current cost

maxLinesCalculator measures how much text fits by creating hidden DOM nodes and calling scrollWidth / getBoundingClientRect() in a binary search, then scales the font. Every Bible slide change re-arms it. The existing cache (500 entries) softens it but doesn't remove the DOM work.

Fix options

  1. Math estimate (Method 01). Estimate lines from font-size and slide width in JS before anything renders; never enter the binary search for content that provably fits.
  2. Canonical-content cache. Key the fit result on the normalized slide content + geometry, not on JSON.stringify({…}) of unstable options, so identical verses reuse results.
  3. First-render guess + deferred re-measure. Show the estimate instantly; re-measure once off the critical path and correct with a transition.
  4. Canvas-ish measurement. Use canvas.measureText in the worker instead of live DOM layout nodes.
