Method 02

Nearest-Punctuation Splitter

A simple, O(n), deterministic splitter that never cuts mid-word and never cuts mid-sentence when a boundary is reachable. The hard invariant is testable.

The hard invariant (non-negotiable)

Rule: a split may never land inside a word, and must never land mid-sentence when a sentence/clause boundary exists inside the search window.

PriorityBreak pointWhy
1 (best). ! ? sentence endslide closes after a full thought
2; : — – clause endbreaks between clauses
3, phrase pauseonly if no better boundary in range
4space (word boundary)last resort for one huge sentence with no punctuation

When a single sentence is longer than the budget, a space break is unavoidable and acceptable — it is still never mid-word. Rejecting space breaks entirely would mean slides longer than the char budget.

Algorithm sketch

function nextBreak(text, start, maxChars, tolerance) {
  budget   = start + maxChars
  hardLimit = min(len, budget + tolerance)
  scanFrom  = max(0, hardLimit - budget*2)   // bounded window
  fallback  = -1                             // clause > comma > space
  for (i = hardLimit; i >= scanFrom; i--) {
    c = text[i]
    if ('.!?'.includes(c)) return i + 1      // rightmost sentence end wins
    if (/[;:—–]/.test(c) && fallbackPrio(fallback) < 2) fallback = best(fallback, i, 2)
    else if (c === ',' && prio(best(fallback)) < 1) fallback = best(fallback, i, 1)
    else if (c === ' ' && fallback === -1) fallback = i  // priority 0
  }
  return fallback >= 0 ? fallback + 1 : hardLimit + 1
}

Enforceable test invariants

  1. No mid-word: at every junction, the original text has a space or punctuation at the boundary — reconstruct by joining slides with a space and compare to the normalized input.
  2. Reversible: normalize(slides.join(' ')) === normalize(original) for every input.
  3. Budget: each slide ≤ maxChars + tolerance.
  4. Preference: when a period exists in the window, a slide never ends on a comma/space to its right; when a semicolon exists, it beats a nearer comma.
  5. Bracket safety: a short [marker] is never split across slides.

Pros / cons

Pros

  • ~0.001–0.04 ms — ~1000× faster than the current splitter
  • Deterministic, pure function, trivially unit-testable
  • Fixes the maxSegments=3 bug: remove the hard cap so longVersesChars is honoured
  • No DOM, no geometry coupling

Risks

  • Does not guarantee the slide actually fits the output — char count ≠ pixel fit
  • Sentence ends far from the budget produce short slides (correct, but visually uneven)
  • HTML-rich verses need tag-safe handling (reopen/close tags like FreeShow's splitHtmlText)

Verdict

Cheapest correct fix and the natural first step. Use it to produce clean sub-verse units; layer Method 01 on top if real output fitting is needed.
