Method 01

Where the HTML Template Does the Splitting

FreeShow's smartSplit model: estimate how many lines fit the scripture template geometry at build time, so the expensive output autosizer never runs.

Why this is the highest-leverage fix

FreeShow's smartSplit estimates the fit in pure JS from the real template CSS — it never measures the DOM. If the split already fits the output, the whole maxLinesCalculator binary-search-measure cascade (the documented #1 bottleneck) is never triggered for Bible slides.

How FreeShow models a fit

PropertyModel
charsPerLine≈ font-size × 0.5 (average char width)
linesCountfrom the template slide's inline CSS: height − padding(2) ÷ line-height
Spacing rulessame-part sub-verses → space; consecutive verses → +1 line if versesOnIndividualLines; non-consecutive → +2 lines (paragraph break)
estimatedLines(text) =
    ceil( effectiveWidth(text) / charsPerLine )

fit(text) = estimatedLines(text) <= linesCount

What to build

  1. Read output geometry once. Pass the configured output resolution, slide width/height, padding, font-size, line-height into the splitter.
  2. Greedy pack. Try to add the next verse / sub-verse to the current slide; if estimated lines exceed linesCount, close the slide and start a new one.
  3. Share the model. Control panel and output pages must use one line-estimation function, else preview ≠ broadcast.
  4. Fallback. Keep versesPerSlide when no template geometry is resolvable.

Pros / cons

Pros

  • Eliminates the DOM-measuring autosize path for Bible content entirely
  • Deterministic, testable, no layout jank
  • Handles template changes (theme font sizes) automatically
  • Matches FreeShow's proven production model

Risks

  • Couples the control panel to output geometry (FreeShow does exactly this)
  • Line estimation is approximate — edge fonts/kerning can drift (±1 line), needs a safety margin
  • Both layers must be kept in lockstep or previews mislead
  • Higher implementation surface than a pure text splitter

Verdict

Best long-term architecture. Pairs perfectly with Method 02: nearest-punctuation splitter produces the clean sub-verse units, this method packs them into slides that actually fit.
