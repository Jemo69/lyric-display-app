PLAN — LYRICDISPLAY MOBILE SUPER-PR

MERGE #21 AND #22 INTO ONE SHIPPABLE mobile/ APP

Two independent Flutter controllers landed at the same time. Both do the same job — let a volunteer drive lyrics from a phone on church Wi-Fi, no cloud, no pairing server. Neither is shippable alone. This plan crates them into one production app: server mDNS beacon + resilient discovery + full lyric control.

PR #21 feat/flutter-mobile-controller → mobile/ · PR #22 t3code/6985dfb2 → lyric-display-mobile/ · Base: master

VOCABULARY — HOW WE TALK ABOUT THIS
  • Volunteer / Operator — the person running lyrics from the phone during service. Not "user."
  • Church Wi-Fi — flat LAN, no internet, multicast may be blocked. Offline-first.
  • 6-digit join code → JWT 24h in secure storage. Silent re-auth, re-pair on 401.
  • Discovery — mDNS _lyricdisplay._tcp + parallel subnet sweep on :4000/api/health + manual IP + desktop-QR fallback.
  • Lyric control — next/prev/goto, setlist load/reorder, output toggle/blackout, live sync via Socket.IO.
  • Phone / Tablet — one codebase, single-column ships now, NavigationRail two-pane at ≥600dp.
MAIN GOAL — ONE SENTENCE
VOLUNTEERS RUN THE ENTIRE SHOW FROM A PHONE, FOUND AUTOMATICALLY ON CHURCH WI-FI.

No typing an IP. No desktop required. No cloud. The desktop advertises, the phone finds it, pairs once, drives lyrics, setlist, Bible quick-load, and outputs — with reconnect, queue, and heartbeat surviving flaky Wi-Fi.

WHERE THIS IS HEADING: LyricDisplay becomes the ProPresenter killer for churches — desktop is the source of truth, phone is the stage remote. This super-PR is the foundation for congregation display parity later.
